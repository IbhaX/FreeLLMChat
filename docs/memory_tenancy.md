# Multi-Tenant Memory Isolation — Architecture & Security Report

## 1. Existing architecture (audit)

Pre-migration state, verified by reading the code and scanning Astra:

| Collection | Purpose | Vectorize | Docs | Had `user_id`? |
|---|---|---|---|---|
| `mem_short` | per-turn conversation context | nvidia/NV-Embed-QA | 202 | no |
| `mem_long` | durable extracted facts | nvidia/NV-Embed-QA | 23 | no |
| `evidence` (`ASTRA_EVIDENCE_COLLECTION`) | research evidence vectors | nvidia/NV-Embed-QA | 225 | 10 (`anon`, written post-change) |

Every read was effectively global: `recall_long` had no filter,
`recall_short` filtered only by `conversation_id`, `memory_graph` scanned
unfiltered, `agents.get_memory_text` returned the union of all SQL
`Memory` rows, `/admin/memories` listed/created/deleted unscoped rows.
`RoleplayRoom` already enforced `owner_id`; `ResearchRunV2` has
`owner_id`, `Conversation` and `Memory` did not.

Audit report: `docs/migration/tenancy_audit_*.json` (generated by
`scripts/migrate_memory_tenancy.py --dry-run`).

## 2. Tenant model

* Tenant key: `u<account id>` — the immutable `users.id`, never email or
  display name; derived only from verified auth (`User` object resolved
  by `optional_user`/`require_user`), never from request payloads.
* `anon` — auth-off single-tenant mode; sees only `user_id="anon"` docs
  and unowned SQL rows. Distinct namespace from every `u*` tenant.
* `__legacy__` — quarantine tenant stamped by the migration on docs whose
  owner cannot be traced. Matches no real tenant filter → invisible to
  all users, preserved for audit. Writes into it are refused.

## 3. Enforcement layers

| Layer | Mechanism |
|---|---|
| `astra_memory.py` | `user_id` stamped on every insert; `{"user_id": tenant}` inside every `find`/`find_one`/`delete_one`/`update_one` — including fallback non-vector queries. Empty tenant → `PermissionError`/empty; `__legacy__` writes refused. Per-tenant dedup in `store_long`. |
| `memory_service.py` | `MemoryService` facade — `create/retrieve/search/update/delete/list/consolidate/summarize/retrieve_related/inspect_memory_graph`; derives tenant from the verified user. |
| `memory_graph.py` | `_fetch_docs` filters by tenant in Astra; similarity edges computed only within the tenant's docs → cross-tenant edges impossible; cache keyed per tenant. |
| `agents.py` | `get_memory_text`/`run_agent`/`stream_agent` take `user`; SQL `Memory` select filtered by `owner_id`. |
| Routes | `openai_routes`, `group_routes`, `agent_routes` pass the resolved user/tenant through (incl. `asyncio.to_thread` background calls). `/admin/memories` CRUD filtered by `id + owner_id` (cross-user → 404); body-supplied owner ids ignored. `/admin/memory/graph` serves the caller's tenant only. |
| `evidence_store.py` | `_index_evidence` stamps `user_id` resolved via `ResearchRunV2.owner_id`; `recall_evidence` filters `{run_id, user_id}`; `delete_run_vectors` accepts optional tenant. |
| SQL | `Memory.owner_id` column + migration (`app/db.py`), indexed, `ON DELETE SET NULL`. |
| Roleplay | `RoleplayRoom.owner_id` already enforced on list/get/create; rooms/worlds are per-user by construction. |

## 4. Fail-closed guarantees

* Empty/missing tenant → no reads, no writes, empty graphs.
* Cross-tenant doc id knowledge is useless: `get_doc`/`delete_doc`/
  `update_doc_text` match `_id AND user_id`.
* Forged ids can't widen access: the tenant arg only ever scopes *down*.
* `graph_cached("")` → empty graph; per-tenant cache slots can't serve
  another tenant's data.
* `extract_and_store` validates the tenant before touching the gateway —
  background jobs carry the verified tenant explicitly.

## 5. Migration

`scripts/migrate_memory_tenancy.py`

```text
--dry-run        audit + report, no writes (default)
--apply          backup → stamp user_id → report  (needs NOVA_MIGRATION_ACK=1)
--rollback FILE  restore pre-apply state from the backup JSON
```

Verdicts: `verified` (already stamped), `traced` (evidence →
`ResearchRunV2.owner_id`), `traced_anon` (run exists, no owner),
`quarantine` (untraceable → `__legacy__`).

Live audit result: **440 docs quarantined, 10 verified** — no doc had a
traceable owner, consistent with "never guess ownership". Applying will
make pre-tenancy memory invisible (as required) while preserving it for
audit; new memories land correctly tenant-scoped.

## 6. Benchmark (live Astra, `scripts/benchmark_memory.py`)

| Operation | median |
|---|---|
| filtered `$vectorize` recall | 1130 ms |
| filtered scan `find` | 867 ms |
| filtered `delete_one` | 850 ms |

Latency is remote-call-dominated (Astra + NVIDIA vectorize); the
`user_id` filter adds no measurable overhead. All memory calls already
run via `asyncio.to_thread` off the event loop.

## 7. Threat-model note

Isolation is application-enforced on shared collections — the Astra
application token can read all data; enforcement relies on every query
passing through the tenant-filtering service layer (verified by tests
that inspect the actual filter dicts). If the threat model ever requires
database-enforced separation, options are per-user Astra tokens,
per-tenant keyspaces, or client-side encryption keyed per user — none
needed at this scale.

## 8. Verification
